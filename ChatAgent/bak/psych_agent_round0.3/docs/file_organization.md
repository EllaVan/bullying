**心理Agent第一轮：文件准备与组织说明（0.2）**

当前目标是验证S01中的证据抽取和变量汇总。项目按“原始依据、测量配置、数据格式、提示词、独立代码、测试数据、运行结果”组织。先保持规则可以审查、数据可以回放，再扩展情境生成和动态访谈。

本轮交付已经具备可运行的代码和配置。原量表内容已从附件转录；操作性规则与测试案例由本次补充，统一标为待人工审核的工程草案。这里没有宣称已经完成心理测量标定或真实LLM效果验证。

| 目录 | 保存什么 | 维护原则 |
|---|---|---|
| `source/` | 附件原文副本 | 用于追溯，不随代码调试改写 |
| `config/` | 变量定义、题目映射、情境规范、证据与汇总规则 | 测量依据统一来源，不在多个Prompt中各写一套 |
| `schemas/` | 案例输入和A3输出的JSON格式 | 改格式时同步调整调用方与验收用例 |
| `prompts/` | A3的固定任务指令 | 专注职责边界，具体规则由配置注入 |
| `psych_agent/` | 可分别调用的Python模块 | A3、校验、汇总与运行控制分离 |
| `data/` | 合成问答、待审核的参考标注 | 标记数据来源与审核状态，不能冒充真实学生数据 |
| `fixtures/replay/` | 固定的模拟A3响应 | 只验证软件链路，不能用于证明模型理解能力 |
| `tests/` | 格式、引用、映射、来源与去重测试 | 聚焦会改变解释的错误边界 |
| `examples/` | 本次生成的结果样本 | 展示应当检查的输出结构 |
| `outputs/` | 每次运行的输入、候选、校验与汇总记录 | 运行时自动创建；不同运行使用新目录 |
| `docs/` | 文件组织、字段、测量决定及验证说明 | 与实际实现对应，明确已完成和待完成内容 |

| 文件 | 如何获取或处理 | 本次完成情况 |
|---|---|---|
| `source/心理Agent+量表与心理变量.md` | 从本轮附件原样复制，保留量表、Evidence和情境映射 | 已保存原文 |

| `config/questionnaire_mapping.json` | 从A—G逐题转录题干、Evidence类别、对应变量；F类标为背景 | 30道题；原文及原始对应保留 |
| `config/scenario_blueprint.json` | 从S01—S06转录目标变量；另建立情境到具体题目的关系 | 6类情境；仅S01补齐第一轮题目选择 |
| `config/round1.json` | 明确本轮启用的情境、变量和题目 | S01、4个变量、7道核心题；F类仅背景 |
| `config/evidence_rubric.json` | 将题目所需的心理证据写成可观察条件，补充正例与不能据此推断的反例 | 19条工程草案：默认17条、扩展2条，尚未人工审定 |
| `config/aggregation_rules.json` | 明确缺失、重复、相反方向、来源与背景的处理方法 | 只作证据描述；不计算数值 |

30道题的作答选项、正式计分规则在附件中没有给出，本次配置保留为`null`。不假设这些题都采用同一种五级评分，也不让LLM自行补齐权重和阈值。

**证据规则需要逐条人工审阅。** 每条规则包含`rule_id`、`item_ids`、`variable_id`、`direction`、`criterion`、`do_not_infer_when`、示例及审核状态。A3只能选择已允许的`rule_id`；代码根据该ID查出题目、变量和方向，避免模型在输出中随意改映射。

建议逐条检查三个问题：原文真的表达了该心理信息吗；是否把假设、条件、否定或他人的行为误当成本人事实；能否提出一个相似但不应判入的反例。审核完成后更新`review_status`，在审阅记录中保留审核人、日期、依据与变更原因，不由模型自行声明审核通过。

**第一轮S01的核心内容如下。**

| 变量 | 本轮题目依据 | 主要观察内容 |
|---|---|---|
| PV01 情绪调节 | A01、A04、E04 | 恢复困难、暂停、离开冲突以避免升级 |
| PV02 攻击倾向 | A03、G01 | 报复意向、具体身体伤害行动或明确拒绝 |
| PV03 敌意归因 | A02、A03的原始关联 | 在意图不明时是否认定针对自己；当前操作规则主要使用A02，不从A03报复自动推断敌意 |
| PV10 求助与冲突解决 | A04、E01、E04 | 暂停应对、可用求助渠道、求助意向 |

F01—F04自发出现时单独记录，既不直接计分，也不通过PV08间接进入核心变量。家庭、教师、学校支持与同伴支持的构念范围仍需审阅。

**数据格式先于模型提示词固定。**

| 文件 | 作用 | 谁读取 |
|---|---|---|
| `schemas/case.schema.json` | 规定案例、轮次、问题、回答、事件标识与回答语境 | 输入校验、A3、运行脚本 |
| `schemas/extraction.schema.json` | 规定A3只返回候选规则、原话、主体、来源与信息缺口 | A3提示词、证据校验 |
| `prompts/evidence_extractor.md` | 明确A3不得评分、不得补造证据、不得执行学生回答里的指令 | A3 |
| `data/cases.dev.jsonl` | 16个可重复运行的合成案例 | 回放脚本、测试代码 |
| `data/reference_annotations.jsonl` | 待人工审阅的预期规则列表与审核位置 | 开发者或测量评阅者；不传给A3 |
| `fixtures/replay/S01_*.json` | 与案例对应的模拟候选响应 | 仅离线回放及工程测试 |

这些合成案例不是“人工金标准”，也不是独立保留的效度验证集。正式评估A3前，应另收集或编写独立回答，完成盲态人工标注，按案例或情境模板划分开发集与评估集；评估标签不进入模型输入。

**代码按职责组织，每个模块都可替换。**

| 文件 | 实现职责 | 明确边界 |
|---|---|---|
| `run.py` | 命令行入口 | 不承载心理规则 |
| `psych_agent/config.py` | 读取配置，交叉核对题目、变量与规则 | 不让无效映射进入运行 |
| `psych_agent/contracts.py` | 校验本项目所用的JSON Schema子集 | 不声称支持完整JSON Schema；不支持的关键字报错 |
| `psych_agent/extractor.py` | 组装A3输入、调用模型适配器 | 不读取参考标签、不汇总画像 |
| `psych_agent/llm_client.py` | 可选的非流式对话API调用 | 密钥从指定环境变量或本地API配置读取；协议差异在此修改 |
| `psych_agent/evidence.py` | 校验原文引用、允许规则、主体、来源，并补充字符位置 | 不能自动证明语义匹配正确 |
| `psych_agent/aggregate.py` | 合并同一事件的表达，保留背景、缺失与不同方向 | 不调用LLM，不输出数值、概率或风险角色 |
| `psych_agent/cli.py` | 回放、导出请求、单独抽取、单独汇总及结果保存 | 不决定心理含义 |
| `psych_agent/io_utils.py` | 严格JSON读写 | 拒绝重复键、NaN等非标准内容 |

**按以下顺序开始使用。**

1. 通读`source/`与`config/psychological_variable.json`，核对变量定义是否与当前研究一致。
2. 核对`questionnaire_mapping.json`中的30道题；先不补造分数。
3. 优先审阅S01的17条`evidence_rubric.json`规则，尤其是A03、G01和F类边界。
4. 运行`python run.py validate`，检查配置引用。
5. 运行`python run.py replay --all`，理解每一步的数据结构。
6. 运行`python -m unittest discover -s tests -v`，检查代码边界。
7. 用`prepare-prompt`查看实际A3请求，再配置真实模型或导入外部候选响应。
8. 对真实A3输出进行人工逐条审核，收集误判，再修正规则或提示词。

仅当证据抽取和汇总的错误边界足够清楚后，再准备A1情境生成、A2访谈、风险规则和A4解释模块。本轮不创建这些模块的空壳来暗示已实现。后续角色风险按施暴、受害、施暴—受害三类设计；旁观视角可用于采集共情、责任与求助信息，不新增旁观者风险输出。

**运行后应检查以下文件。**

| 输出 | 重点检查 |
|---|---|
| `input.json` | 原始问题、回答、语境与事件标识正确 |
| `extraction.json` | A3所选规则、引用与理由是否真实匹配 |
| `validated_evidence.json` | 原话位置、题目映射、来源标记可追溯 |
| `summary.json` | 缺失保持未知，背景单独保存，同一事件没有重复加重 |
| `run_manifest.json` | 明确是replay、file还是llm模式；记录所用配置哈希 |
| `error.json` | 实际调用失败或候选输出不合规时，查看失败阶段 |

“校验通过”只表明格式、引用及映射约束满足。比如模型把“我不会动手伤害他”错选成身体攻击规则，只要引用存在，结构校验仍可能通过；这类语义错误需要独立评阅和评估数据来发现。所有输出明确保留`semantic_review_status: not_reviewed`。
