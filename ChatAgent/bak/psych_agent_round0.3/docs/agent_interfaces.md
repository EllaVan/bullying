# Agent 接口与测量边界（0.3.0）

测量内容来自原附件；调度、覆盖和证据关联由程序管理。LLM 提供情境文字、问题文字、候选观察或报告解释，不自行改变题目—变量映射。

## 模块职责

公开协议位于 `psych_agent/dialogue_contracts.py`。输入和输出均为普通 Python 字典，可按 JSON 保存。

| 模块 | 独立接口 | 输出 | 边界 |
| --- | --- | --- | --- |
| A1 情境 Agent | `generate(task)` | 情境文字、约定事实 | 表达可变化；形式、关系、意图清晰度等冻结事实必须匹配蓝图 |
| 测量控制器 | `next_action()`、`commit(result)` | 当轮任务、覆盖状态、停止决定 | 根据量表单元和缺失槽位调度，不读取风险结果 |
| A2 访谈 Agent | `ask(task, history)` | `{"question": "…"}` | 根据当前目标提问，不决定心理变量得分 |
| A3 观察 Agent | `extract(task, turn, history)` | 单元观察、原话、槽位、规则引用、背景 | 只处理本轮允许的测量范围，不判定风险角色 |
| 证据校验器 | `validate_turn(...)` | `ValidatedTurn` | 验证结构、原话位置、上下文、规则和变量范围 |
| 画像构建器 | `build_profile(state, cfg)` | `profile.json` | 按变量、原题单元、事件、条件、参照方式组织证据 |
| 风险引擎 | `assess(profile)` | `risk_result.json` | 默认组织角色线索；模型计算可替换 |
| A4 画像解释 Agent | `report(profile, risk)` | 可追溯解释 | 引用已有证据和风险结果，不计算或改写风险概率 |

`dialogue_runner.Agents` 通过依赖注入组合这些对象；`run_session` 负责本地编排和文件记录。各模块不依赖服务端框架或数据库。`JsonTransport` 是独立的 JSON 请求和审计适配器；每个 Agent 可连接不同的模型配置。

## 从原题到多轮提问

映射经过四层：原题定义 `questionnaire_mapping.json` → 情境绑定 `scenario_blueprint.json` → 测量单元 `measurement_units.json` → 访谈计划 `interview_policy.json`。多轮规则独立位于 `dialogue_rubric.json`。

原附件共 30 题，其中 26 题属于核心测量，F01—F04 为背景。本轮将 26 道核心题整理为 30 个单元。数量为 30 是拆分和复用的结果，不代表把四道 F 类题纳入核心。

| 原题或例子 | 本轮处理 | 避免的问题 |
| --- | --- | --- |
| E01/E02/E03/E04/E05 | 分别保留求助渠道、表达、顾虑、降级应对、兼顾他人与自我保护等单元 | 一句“找老师”不能完成全部 PV10 测量 |
| D04 → PV08/PV10 | 保留原始双变量映射；S01 只选择 PV10；朋友关系条件满足后才启用 | 部分映射不删题，也不越界补入 PV08 |
| E03 → PV10 | 可在 S01 扩展计划中启用，不要求同题所有变量都出现在全局计划 | 题目是否启用与本轮是否完成分开 |
| A02/A03 | 区分归因、反刍、报复表达，保留各自来源 | 一个问题的回答不自动代表相关构念都完成 |
| B03、C05、G03 | 按原题不同方面拆分单元，再根据情境选择变量 | 不把一个复合原题强行压成一条总分 |
| E02 | 使用 `task_performance`，让学生尝试组织一句表达 | “我会说清楚”不能直接等同于实际表达表现 |
| F01—F04 | 仅记录自发背景；`included_in_core_or_risk=false` | 背景不进入十变量核心证据或风险输入 |

每个单元显式定义原题、变量、参照方式、适用条件、所需信息槽位和允许规则。题目进入情境时只选择原题映射与情境允许范围内的变量。D04 的两种路径由 `s01_extended` 和 `s01_friend` 的独立回放验证。

## 状态、规则与证据编号

单元状态为 `not_asked / partial / covered / ambiguous / declined / not_applicable`。回答“不会报复”可以完成相应测量；风险方向较低不等于没有回答。模糊回答、预算不足、拒答和不适用分别保存，缺失不记为低风险。

A3 返回 `rule_id`，例如某条 `DR_…` 规则；程序依据该规则取得变量和方向。`evidence_id`（`DEV_…`）是某个学生、某轮原话产生的一条证据实例编号，不应与规则编号相同。`observation_id`、`unit_id`、`question_id`、`turn_id`、`scenario_instance_id`、`condition_id`、`event_id` 分别标识观察、测量任务、提问、轮次、情境实例、条件和事件。

原话引用必须在本轮回答中逐字且唯一出现，保存 Unicode 字符位置；指代补充通过 `context_turn_ids` 引用同情境中已完成轮次。程序校验不将“能够解析 JSON”当作证据已有效，也不将机械校验声称为语义准确性验证。

## 情境假设、经历和重复信息

`reference_frame` 区分假设选择、习惯性自述、真实事件自述、一般看法、表达任务表现和来源不明。自发说起的真实经历有独立事件关联；第三方或来源不清的内容不进入学生核心画像。只有主体是学生自身、参照方式匹配单元时，观察才可以更新该单元覆盖。

一个单元可通过多轮 `partial` 补齐必需信息。画像按“变量 + 单元 + 事件 + 条件 + 参照方式 + 参照时间”组织观察。重复表达保留引用，但不会仅因同一句意思多出现几次就提高证据强度。不同条件保留不同组，不把条件差异直接解释为矛盾；同组方向冲突也保留，不取平均消除。

S02 保留原设计的旁观视角，用来观察同理心、责任和求助应对；风险结果仍仅输出施暴、受害、两者兼有三种角色，不新增“旁观者风险概率”。

## 风险模型契约

`EvidenceRiskEngine` 按原变量表的主要风险作用组织因素，不输出权重、量表总分、高中低等级或虚构概率。PV10 作为共享的求助与应对线索单独列出。

外部模型可以实现 `RiskEngine.assess(profile)`，再注入 `Agents`；也可以离线读取 `model_input(profile)` 的 JSON，以 `ExternalPredictionRiskEngine` 导入预测文件。前者方便后续接入本地模型，后者可先独立验证数据接口。

预测文件需包含 `session_id`、`input_hash`、`synthetic`、`model_id`、评估目标、时间范围、三个概率、置信度及验证状态声明。程序检查这些字段和概率一致性，验证状态字符串本身不是模型已经有效的证明。

三个概率采用边际与联合语义：

- `bully = P(施暴卷入)`；包括两者兼有者。
- `victim = P(受害卷入)`；包括两者兼有者。
- `bully_victim = P(施暴且受害)`。

三者不要求和为 1，联合概率必须满足 `max(0, bully + victim - 1) <= bully_victim <= min(bully, victim)`，不会假定两者独立而自动相乘。若后续模型输出的是三个互斥类别，需在模型适配层明确转换语义。

`confidence` 没有外部定义时填 `null`。覆盖率不是置信度；假设性选择不是已经发生的霸凌事实。当前实现提供这些区别的数据接口，尚未提供训练好的现实或未来卷入预测模型。

## 扩展顺序

修改心理测量内容时，先更新原题与变量依据，再更新情境绑定、单元、规则和计划。只改善 A2 的语言组织时，替换 A2 实现即可；只优化抽取时，保留 A3 输出契约；只接入风险小模型时，替换风险引擎，A1—A3 无须依赖它。

快照记录配置、提示词和 schema 指纹。恢复时重建已完成轮次，检查存储状态与校验结果一致，避免新测量定义下继续沿用旧覆盖结论。该机制是本地实验可复现性检查，不包含服务端版本管理系统。
