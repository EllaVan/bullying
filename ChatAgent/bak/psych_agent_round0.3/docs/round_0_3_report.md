# 第 2 轮代码修改与功能报告：0.3.0

日期：2026-09-09。修改基线：0.2.2。目标：依据已上传的量表、心理变量和 Agent 设计，完成本地情景多轮对话到校园霸凌风险画像的功能链路，各接口可以独立验证和替换。

## 本轮修改

1. 把原有单案例 A3 抽取流程扩展为 A1 情境生成、A2 多轮提问、A3 候选观察、确定性测量控制与画像组织、独立风险引擎、A4 解释的完整命令行流程。
2. 依据原题配置 30 个测量单元，覆盖 26 道核心题；新增 69 条多轮观察规则、6 类情境实例定义和 5 个访谈计划。F01—F04 继续只记录自发背景。
3. 按单元所需信息管理追问、跨轮补全、拒答、条件不适用、预算停止和结束报告；不以是否提到某个变量代替测量完成。
4. 实现 E03/D04 的部分变量绑定，保留 D04 原始 PV08/PV10 关系，S01 仅启用 PV10，并通过明确的朋友关系条件控制适用性。
5. 为原话、规则、观察、轮次、情境、条件和事件建立独立编号；分开假设回答、习惯自述、真实经历、表达任务表现和第三方内容。重复表达与条件变化在画像中保留来源，不直接累加成分数。
6. 新增十变量画像、三角色相关因素、可插拔风险接口、外部预测文件校验及 A4 引用检查。没有模型时概率和置信度保持 `null`。
7. 提供逐轮输入输出、按 Agent 保存的原始 LLM 响应、连续编号快照、失败阶段记录和显式续跑。修复快照反复覆盖可能造成总快照与最终画像不一致的问题，最终画像已经与独立重算结果一致。
8. 新增接口说明、运行说明、完整合成回放结果、修改清单和后续每轮报告模板。旧单案例流程继续保留。

## 验证结果与实际边界

- 110 项自动化测试通过：原 69 项，新增 41 项。覆盖部分映射、参照方式、引文和规则越界、跨轮补全、拒答、预算、去重分组、配置指纹、恢复和风险接口。
- 五套合成多轮回放均通过，分别为 6、8、9、28、56 轮。普通同学与朋友条件分别验证 D04 不适用和只选择 PV10。
- 完整回放包含 6 情境、3 形式、10 变量。55 个计划内单元实例中 53 个适用单元完成、2 个不适用；这是测量任务覆盖，不是心理测量信效度。
- 四 Agent 均已通过本机模拟 HTTP 服务运行完整调用链，验证实际 HTTP 客户端、JSON 解析、接口调用和输出保存；没有调用你的智谱账号。
- 完整 56 轮总快照、覆盖报告和画像一致；从保存快照独立重算的画像指纹相同。
- 验证环境为 Linux / Python 3.12。未在 Windows 实机或用户所配置的真实模型上验证。

固定回放使用预制的合成答案和 A3 响应，验证的是代码功能及边界，不声称已经验证 LLM 的语义准确率。本轮按当前任务假设推进架构和功能，未把语义评估扩展为阻塞交付的前置工作。

当前可完成“情景多轮对话 → 十变量证据画像 → 三角色风险线索解释”。经标定的现实或未来卷入概率不属于已完成结果；仅凭现有题目与变量定义不能产生这样的模型。代码提供接入位置，而不会用任意权重填补这一缺口。

系统后端、数据库、账号管理、线上部署和干预推荐不在本轮范围内。

## 接下来怎么运行

解压后保留自己的 `config/llm.local.json`，在项目目录运行：

```bash
python run.py dialogue-validate
python run.py dialogue-replay --plan full
python run.py interview --plan s01 --llm-config config/llm.local.json
```

前两条不需要 API；第三条开始真实交互。一次运行结束后先查看 `report.md` 与 `coverage_report.json`，如需研究具体 Agent，再使用 `scenario / ask / observe / risk / report` 单独复现。

完整说明见 `multiturn_usage.md`，接口边界见 `agent_interfaces.md`，逐文件变化见 `change_manifest.json`，机器可读状态见 `feature_status.json`。之后每轮修改应更新同样的“本轮修改、已完成、待完成、验证与限制”记录，模板见 `change_report_template.md`。
