# 0.5.2 需求追踪与0.4问题闭环

本表对应0.4以来已提出的问题。紧急风险处理、人工复核工作流、隐私权限按本轮要求暂不实现。

| 已提出问题 | 0.5.2处理 | 验证位置 |
|---|---|---|
| 角色输出不应继续称为概率 | A4使用互相独立的0–100风险分数；不归一化、不要求合计100 | `risk_engine.py`、两个风险Schema、A4测试 |
| 保护性变量方向错误 | 保护变量按1-value反转后聚合 | `risk_scoring.json`、`risk_engine.py` |
| 不知道/拒答不能自动变成中间分 | 未观察值为null；覆盖不足时角色分数为null | `profile.py`、最低覆盖门槛 |
| 求助渠道与成人信任混淆 | PV10拆分facet；“找老师但不确定是否有用”保留渠道能力 | rubric、facets、提示词 |
| A3格式错误或非法上下文中断 | 一次结构修复、清理非法引用；失败后空观察并继续 | `turn_extractor.py`、`dialogue_contracts.py` |
| 简短回答导致流程中断 | 每目标最多一次换角度追问，仍低信息则推进并统计比例 | controller、policy、报告 |
| 假设、真实经历、旁观混淆 | Experience记录独立；第三方只作背景 | `experience.py`、经验Schema |
| 固定模板缺少情境差异与跳题 | 计划/情境/条件驱动动态追问 | dialogue配置与controller |
| 三类角色混成一个概率模型 | 三类角色独立按配置权重计算 | `risk_scoring.json`、`risk_engine.py` |
| 缺少阈值与完整度 | 报告显示35/65及双重40/70阈值、覆盖度和不足状态 | reporter、report policy |
| 输出过于简略 | 恢复0.4目录组织，报告含来源、facet、Evidence、经验、阈值、限制和追踪 | handover、reporter |
